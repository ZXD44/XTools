# ui-rs

Rust port of `scripts/ui/`, bridged with PyO3. Generated by rust-anything.

## Functions

- `t` (`scripts/ui/i18n.py:109`)

## Loop

```sh
rust-anything record .   # record what the Python code does
rust-anything build .    # build the PyO3 module
rust-anything diff .     # run the recorded cases against Rust
rust-anything shadow .   # run both in the app, log mismatches
rust-anything gate .     # fmt, clippy, tests, unsafe, API, diff
```

Record on Windows, `PYTHONPATH` must point at the repo root (the driver imports
`scripts.ui.i18n`, which imports `scripts.config`):

```sh
set PYTHONPATH=%CD%
rust-anything record rust/ui-rs
```

## Status — 2026-11-26 (rust-anything 5.0.1, Windows 11, Python 3.14.7, Rust 1.99.0)

| Check | Result |
| --- | --- |
| `diff` | **211/211** recorded cases match |
| `fuzz --time 15` | **786/786** fresh cases match (seed 827302844) |
| `gate` | **passed** — fmt, clippy, test, unsafe, lockfile, ported, size, literals, api, behavior |
| `bench` | **1.8x slower** — 283 ns/call in Python vs 524 ns/call across PyO3 |

`bench` says not to ship this unit for speed: a per-key dictionary lookup is smaller than the
cost of crossing into Rust. The port is kept as the verified reference for the Rust-First
standard (`.agent/rules.md` §5) and is **not enabled** — `rust-anything enable` was not run, so
`scripts/ui/` still executes the Python implementation. The next step for speed is a bigger unit
(`scripts/core/` or `scripts/ui/` together with its callers) so one call does more work.

Kept in Python on purpose (`--keep`): terminal rendering, `wave_input` stdin, `get_build_id`
subprocess, config file I/O in `load_lang`/`save_lang`/`set_current_lang`, module globals.
